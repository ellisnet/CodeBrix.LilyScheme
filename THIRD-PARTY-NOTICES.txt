THIRD-PARTY SOFTWARE NOTICES AND INFORMATION

CodeBrix.LilyScheme is a managed, cross-platform Scheme language
implementation for .NET, derived from the GNU Guile project
(https://www.gnu.org/software/guile/). It implements the subset of Guile
needed to run LilyPond's Scheme layer, and it incorporates Guile source
directly: Guile's own .scm modules are vendored and loaded rather than
reimplemented, so that LilyPond's Scheme runs unmodified.

This document is the complete attribution and licensing-compliance record
for this library. Every piece of third-party code, data, script, or asset
that has been adapted, copied, or pulled into CodeBrix.LilyScheme is
recorded here, with its authors, source location, exact upstream revision,
license, the verbatim text of every notice that must travel with it, and
the list of files in this repository derived from it.

--------------------------------------------------------------------------------
HOW THIS FILE IS MAINTAINED
--------------------------------------------------------------------------------

  1. This is a LIVING LEDGER. It is updated in the SAME COMMIT as any
     change that incorporates, adapts, modifies, or removes third-party
     source. It is never allowed to fall behind the code.

  2. Every vendored file gets a row in the inventory in section 1.2, even
     if it shares a license with its neighbours. Guile's module tree is
     NOT uniformly Free Software Foundation copyright -- section 1.3
     documents seven distinct additional copyright holders found by audit --
     so per-file provenance is recorded rather than assumed.

  3. Where an upstream file's own notice does not travel inside the file
     (psyntax-pp.scm is the critical case), the notice is reproduced here
     AND attached to the vendored copy. See section 1.3.1.

  4. Nothing is summarised away. If a notice says it must be reproduced in
     full, it is reproduced in full below, verbatim.

  5. RULE 1 IS CHECKABLE. The standing check is that every .scm under
     src/CodeBrix.LilyScheme/Scheme/ appears in section 1.2's inventory, its
     line count, its per-file copyright years and its upstream mapping -- all
     four places, since a file can be listed in one and missed in the others.
     The 2026-08-15 audit found ice-9/control.scm vendored, embedded and
     LOADED (oop/goops.scm reaches it for let/ec) but absent from all four; it
     was added and the totals corrected. Scheme/lilyscheme/prelude.scm is the
     port's own and is deliberately not inventoried here.

1.1  TWO KINDS OF INCORPORATION -- THE DISTINCTION MATTERS FOR ATTRIBUTION
--------------------------------------------------------------------------------

  (a) VENDORED SCHEME SOURCE.
      Guile's .scm modules are embedded in this library VERBATIM, as
      embedded resources, and are read at runtime by the LilyScheme
      reader. They are not translated, not reformatted, not modified.
      These are literal copies of LGPL-3-licensed material (with the
      exceptions noted in section 1.3), and they carry their upstream
      headers unchanged.

  (b) PORTED C SOURCE.
      Behaviour implemented by libguile in C is reimplemented in C#.
      Where a C# file is a translation of specific libguile source, it
      carries on its `namespace` line:

          namespace CodeBrix.LilyScheme.<Area>; //was previously: libguile/<file>.c;
          // Modified by Jeremy Ellis on <YYYY-MM-DD> as part of the CodeBrix port.

      and preserves the upstream copyright header verbatim above the
      usings. The modification notice is required by LGPL-3 (via GPL-3
      section 5(a)) and is NOT satisfied by the provenance comment alone --
      see section 4.1.

  (c) NOT THIRD PARTY: FRESH CODE WRITTEN FROM PUBLISHED SPECIFICATIONS.
      Parts of this library are written from scratch against published
      specifications -- R7RS, the SRFI documents, and the Tree-IL node
      definitions in Guile's own documentation -- rather than translated
      from Guile source. Implementing a specification is not a derivative
      work of another implementation of that specification. Such files are
      new-in-family, carry no `//was previously:` comment, and carry NO
      fabricated upstream copyright header. They are not listed in this
      document. Where a file's status is ambiguous, it is treated as (b).

  INTERFACE FACTS READ OUT OF libguile (not translated code):
    src/CodeBrix.LilyScheme/Primitives/PrimitiveGenerics.cs carries the list of
    procedure names Guile declares GENERIC-CAPABLE. The list was determined by
    reading the SCM_PRIMITIVE_GENERIC declarations in libguile/*.c and the two
    SCM_GPROC declarations in libguile/print.c, at the version named above,
    rather than recalled or guessed -- the set is not documented in one place
    and getting it wrong is silent (an undeclared name simply never dispatches).
    What was taken is the roster of public procedure names, which is an
    interface fact; no libguile code was translated, and the dispatch itself is
    written against the documented GOOPS behaviour of add-method! /
    enable-primitive-generic! as it appears in the vendored oop/goops.scm.

    src/CodeBrix.LilyScheme/Runtime/SchemeModule.cs (the Printer's program
    printing) reproduces two OBSERVABLE BEHAVIOURS of Guile's procedure printer,
    both of which a consumer's output depends on byte for byte:

      * the external representations themselves -- "#<procedure NAME (formals)>",
        "#<procedure ADDR at FILE:LINE:COLUMN (formals)>" and the low-level
        "#<program ADDR CODE>" -- whose shapes were read out of
        module/system/vm/program.scm's print-program and libguile/programs.c's
        scm_i_program_print at the version named above; and

      * the re-entry latch in that same C function, a file-static flag set around
        the call out to the Scheme printer and never restored when that call
        exits non-locally, after which every procedure in the process prints in
        the low-level form.

    What was taken is the OUTPUT FORMAT and the described behaviour, which are
    interface facts a compatible implementation has to match; no Guile code was
    translated, and the C# is written against those facts.

    src/CodeBrix.LilyScheme/Primitives/SoftPortPrimitives.cs carries a soft
    output port's buffer size (1024 bytes) and transfer quantum (252 bytes).
    Neither was read out of Guile at all: both were MEASURED by running the
    pinned oracle binary over eleven starting buffer fills and recording the
    resulting flush sequences, and the model was then confirmed by predicting
    four fills it had not been shown. The constants are observations of
    behaviour, not transcribed source.
